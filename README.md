# 提示词优化（PromptForge）

DSH（DeepSeek Harness）插件：在输入框旁边加一个星形按钮，用 DSH 已配置的模型把草稿重写成高质量提示词，**只替换输入框内容，绝不自动发送**。开启「自动引用」后，同一个按钮还会把这次任务真正需要的文件与技能追加到提示词末尾。

## 它解决什么问题

一句话草稿（「帮我写一份简历」「检查登录页面与后端路由逻辑是否合理」）信息量太低，agent 只能靠猜。PromptForge 在你按下发送之前，先把这句话补成一个结构清楚、约束明确的提示词，并把这次任务要打开的文件与技能一并列好。

三条设计原则贯穿全部实现：

1. **草稿是你的，改写只是建议。** 结果只写入输入框，发送与否永远由你决定。
2. **正文优先于引用。** 引用是「agent 该打开什么」的索引，不是正文的替代品。任何会抽空正文的改写都会被拒绝（见[正文不会被引用吃掉](#正文不会被引用吃掉)）。
3. **模型只提供线索，索引才是裁判。** 模型提名的路径与技能名，必须经过当前工作区的文件索引和技能目录逐条核对，编造的名字不会出现在提示词里。

## 安装

两种方式任选其一。

**1. 通过 DSH 插件界面**

进入 DSH 的「插件 → 添加插件」，输入：

```
https://github.com/Super-Gagaga/PromptForge.git
```

**2. 克隆后本地构建**

```powershell
git clone https://github.com/Super-Gagaga/PromptForge.git
cd PromptForge
npm test
```

为可由 CLI 管理的 profile 安装时，将 `<profile>` 换为实际名称、`<path>` 换为本仓库路径：

```powershell
dsh plugin --profile <profile> add 'link:<path>/PromptForge'
```

桌面 profile 由 Electron 应用管理，CLI 不支持直接启动它。插件通过 `package.json` 的 `dsh.bundle` 与 `dsh.client` 字段和本包的 `cordis.patch.yml` 装配。

> **改动 Host 半体后必须重启 DSH。** Host 侧代码只在应用启动时装配，刷新页面不会重新加载；只改浏览器半体（`src/client.js`）时，在开启客户端 HMR 的开发环境里刷新页面即可。

## 使用

1. 打开「设置 → 提示词优化」，选择模型与思考强度；需要时修改优化指令。
2. 在输入框写下草稿。**只要输入框有内容**，发送控件左侧就会出现星形按钮。
3. 点击星形按钮，按钮开始旋转表示正在优化。
4. 完成后结果整体替换输入框内容，你检查无误再自行发送。

优化是一次独立的模型请求：它不会改变聊天会话的模型或思考强度，也不会作为消息写入会话历史。请求期间如果你编辑了草稿、提交了消息或切换了会话，较晚返回的结果会被丢弃。调用失败时保留原草稿，错误会显示在按钮提示和设置页。

### 默认改写方式

默认在原意内适度展开：功能需求可明确相关细节，分析和设计任务可补充有用的观察维度；不强制固定模板，也不默认采用最小改写。画面或主题描述可以整理表达与描述重点，但不会自动改成写作、绘图或视频任务，也不会指定未给出的时间与天气。

自定义指令始终优先生效。如果设置里保存的是旧版指令，点「恢复默认」即可换用当前默认值。

### 自动引用文件与技能

「设置 → 提示词优化 → 自动引用」有一项文件开关和一个技能档位。开启后，同一次点击会多做一步：模型在改写的同时提名它认为这次任务需要的文件与技能，Host 再逐条校验，命中的引用被追加到提示词末尾。

- **文件**：模型只给路径或路径片段，Host 拿当前会话工作区的文件索引核对，只有真实存在的路径才会变成 `@路径`（含空格的路径按 DSH 语法写成 `@"路径"`）。模型编造的路径不会出现。追加时带一行标题：

  ```
  Files this task needs:
  @internal/router/router.go
  @web/admin-login.html
  ```

  `@` 的含义由 DSH 自己教给 agent（结尾 `/` 是目录、其余是文件、需要内容时用 `read` 工具读取），所以这里只留标题，不重复解释。
- **技能**：同样的两段式——模型只给技能名，Host 拿该会话可见的技能目录核对，命中的技能以 `/名称` 形式列在末尾：

  ```
  Skills this task may need:
  /make-resume
  /great-resume
  ```

  `/名称` 不是装饰，而是 DSH 的原生调用语法：它扫描用户消息里的 `/名称` 手势并注入该技能正文。因此这里只保留**既允许模型调用、又允许用户调用**的技能，且名称必须符合手势语法（kebab-case）——不符合的名字会被丢弃，而不是写进去当摆设。
- **`@` 路径与 `/` 技能是两种不同的引用。** `@路径` 只是告诉 agent「该读这个文件」，是否读取由 agent 决定；`/技能` 则会在消息发出的那一刻直接注入技能正文。所以技能引用更「重」，这也是它需要档位控制的原因。
- **文件与技能各自独立兜底**：任一侧为空，Host 就会把那一侧的真实候选列出来再问一次（文件列路径，技能列目录）。模型看不到技能目录，所以「帮我写一份简历」这类请求若不给出候选，它只会回答「没有相关技能」——这是 `make-resume` 之类技能能被引用到的前提。
- **候选发现**优先查任务里出现的路径，再尝试根目录和受限遍历；旧索引不支持根目录列表时，回退到任务目录和常见目录名。
- **长度与去重**：已有引用与技能块会合并去重；结果超过输入框长度上限时省略新增引用，保留正文。
- **目录与歧义**：目录引用会校验目录自身，不会替换成某个子文件；路径片段有歧义时不会猜选。

> 关掉开关后，输出格式回到纯文本，模型也不会再收到提名要求。

#### 正文不会被引用吃掉

引用是索引，永远不是正文的替代品。如果某条提名对应的名字原本写在草稿里、却在改写后从正文消失，整次改写会被判定为损坏：保留原稿，并在按钮提示与设置页说明。因此不会把「检查**与的**登录逻辑是否一致」这种被抽空的句子写回输入框。

同理，候选提名只负责补充，不允许删除：一个草稿里从未出现过的名字，只要索引确认它存在，仍然可以被追加。

### 技能档位

技能库是否贴合当前任务因人而异，所以技能不是一个开关，而是四档：

| 档位 | 行为 |
| --- | --- |
| 关闭 | 完全不引用技能 |
| 严格 | 只有请求点名了那项能力、或任务离不开它时才引用，最多 2 个；通常为空 |
| 均衡（默认） | 只引用确实有帮助的技能，最多 3 个 |
| 宽松 | 只要可能有用就引用，最多 3 个；不确定时倾向给出 |

档位只改变**模型在被问到时的取舍标准**，不放宽真实校验：无论哪一档，技能名都必须与技能目录精确匹配，且必须既允许模型调用、又允许用户调用。

升级说明：旧版本用 `referenceSkills: true/false` 保存这个开关，新版本会自动迁移为「均衡 / 关闭」，其余设置原样保留。

### 引用结果与耗时

引用处理有 15 秒总预算。结果会显示在按钮提示与设置页，分四种状态：

| 状态 | 含义 |
| --- | --- |
| 引用已确认 | 本次新增了文件或技能引用 |
| 未发现相关引用 | 问了，但确实没有相关的 |
| 处理未完成 | 部分环节失败（例如索引超时），正文仍然有效 |
| 原稿已保留 | 改写损坏了正文，已回退 |

显示的数量只统计**本次新增**的引用，不含草稿里已有的。

耗时取决于索引是否已热：工作区索引已热时，一次点击约 2 秒（无需提名）到 3 秒（含提名与校验）；首次访问某个工作区需要付一次全量索引扫描，可能到十几秒。

## 工作原理

```
点击星形按钮
   │
   ├─ 1. 改写请求 ──► 模型返回 { prompt, files[], skills[] } 信封
   │                    （一次独立调用，不改会话模型）
   │
   ├─ 2. 正文保护 ──► 改写是否删除了草稿里的路径/提及？
   │                    是 → 保留原稿，结束
   │
   ├─ 3. 校验提名 ──► 文件：文件索引逐条核对（并行查询）
   │                 技能：技能目录逐条核对（精确名 + 双重调用策略）
   │
   ├─ 4. 候选兜底 ──► 任一侧为空？把真实候选列出来再问一次
   │                 文件→<workspace_paths>，技能→<available_skills>
   │
   └─ 5. 追加引用 ──► 标题 + @路径 / /技能，合并去重后写入输入框
```

关键点：**只有一次改写调用是必需的**，第 4 步只在提名缺失时发生。整个链路里模型只负责「提名」，`src/host.js` 里的索引查询才是最终裁判——这就是编造路径无法进入提示词的原因。

## 开发与验证

需要 Node.js，无需安装额外构建依赖。

```powershell
npm run build     # 构建 lib/ 与根目录镜像
npm test          # 构建 + 87 项自检 + 配图存在性检查
npm run figures   # 重新生成 README 配图（需要 Pillow）
```

编辑 `src/`，不要直接修改生成文件。构建会同步生成 `lib/index.js`、`lib/client.js` 及根目录镜像，二者逐字节一致。

| 路径 | 作用 |
| --- | --- |
| `src/host.js` | 设置读写、模型调用、引用校验、HTTP 接口 |
| `src/client.js` | 星形按钮、草稿替换、设置页、中英文文案 |
| `src/shared.js` | 默认优化指令、引用标记、状态归一化、各项上限 |
| `locale/` | 插件列表展示的标题与描述（`zh` / `en`），由 DSH 读取，构建不改写 |
| `tools/selfcheck.mjs` | 隔离设置目录的离线自检，覆盖插件加载、请求、草稿边界、设置保存、失败处理与引用校验 |
| `tools/make-figures.mjs` | 生成 `docs/images/`。配色与文案都从已安装的 DSH 主题与语言包中读出，DSH 更新后重跑即可 |

README 里的配图是**按真实主题变量绘制的示意图**（不是屏幕截图）：`tools/make-figures.mjs` 从 `dsh-client-ui-theme` 解析出每个 token 在当前主题下的实际取值，再从 `dsh-client-ui-conversation` 读取真实界面文案，然后用 Pillow 画图。因此它们不会随 DSH 换配色而过时。

设置保存在 `$DSH_HOME/prompt-forge.json`；未指定 `DSH_HOME` 时使用用户目录的 `.dsh/prompt-forge.json`。每次优化最多接受 60,000 字符，输出上限 4,096 tokens，请求超时 120 秒。

## 常见问题

**按钮没出现。** 星形按钮只在输入框有内容时显示，且需要 DSH 已加载浏览器半体。改过 Host 侧代码后必须重启 DSH。

**出现 `pending (waiting for service: optional)`。** 应更新到本项目的当前构建并重新加载。当前 DSH Cordis 会把 `inject` 对象的键解释为服务名，不支持 `inject: { optional: [...] }`；本插件改用按需服务获取，避免阻塞顶层启用。

**技能引用为空。** 依次检查：技能档位是否为「关闭」；技能是否既允许模型调用又允许用户调用（`SKILL.md` 里 `disable-model-invocation` / `user-invocable` 字段）；以及该技能是否在当前会话可见的技能目录内。档位调到「宽松」可验证档位是否生效——若严格与宽松结果不同，说明链路正常，只是模型在均衡档判断「不够相关」。

**引用块里出现了我不想要的文件。** 关掉「引用文件」开关即可，正文与技能引用不受影响。

**改写把我的句子改坏了。** 这是[正文保护](#正文不会被引用吃掉)要拦的情况；如果仍然发生，请把原草稿与结果一并提 issue。
